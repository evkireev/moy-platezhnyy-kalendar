# Техническое задание: личный платёжный календарь

Версия: 1.1. Дата: 25 октября 2026 года. Уточнено после внешнего ревью.

## 1. Статус документа и приоритет требований

Документ описывает первую локальную версию продукта и критерии её приёмки. Основание — ответы пользователя, concept.md и табличная структура «Пример календаря.xlsx». При расхождениях с concept.md приоритет имеет это ТЗ: здесь учтены поздние решения о входе, красной просрочке, отрицательном остатке, сортировке и выходных. Исходный Excel — визуальный ориентир, а не источник начальных личных данных.

Правила, конкретизирующие неоговорённые технические детали, зафиксированы ниже как решения для реализации. Не добавлять функциональность за пределами первой версии без отдельного запроса.

## 2. Назначение и границы версии

Продукт помогает одному человеку планировать поступления от клиентов и собственные расходы, отмечать фактические оплаты, переносить неоплаченные суммы и видеть прогноз денег на конец каждого дня.

Поставляемое приложение состоит ровно из трёх файлов в папке проекта:

| Файл | Назначение |
| --- | --- |
| index.html | Разметка экранов, форм и таблицы |
| styles.css | Все стили, состояния и оформление |
| app.js | Логика, расчёты, локальное хранение, вход и взаимодействия |

Документы concept.md и tz.md и исходный Excel не относятся к трём файлам приложения. На этапе подготовки ТЗ код не создаётся.

Запуск — двойным щелчком по index.html, через file://. Целевые браузеры — настольные Chrome и Яндекс Браузер под Windows. Работа без интернета, сборки, установки зависимостей и локального веб-сервера. Использовать обычное подключение app.js через defer, без ES-модулей, fetch локальных файлов, CDN, внешних шрифтов и сетевых ресурсов. Интерфейс и сообщения — на русском, единственная валюта — RUB.

В версии 1 нет сервера, настоящего интернет-аккаунта, синхронизации, сторонних интеграций, уведомлений, фильтрации, поиска, графиков, аналитической панели, нескольких счетов и специального мобильного интерфейса. Не делать неработающие кнопки Telegram или Google.

## 3. Участники и права

| Участник | Возможности |
| --- | --- |
| Посетитель без созданного профиля | Создать единственный локальный профиль |
| Владелец с закрытой сессией | Войти по паролю; финансовый интерфейс скрыт |
| Владелец после входа | Все действия со своим календарём, профилем и резервными копиями |

Отдельных ролей администратора, гостей, бухгалтеров и других пользователей нет. После создания профиля повторная регистрация в том же хранилище не показывается.

### 3.1. Локальная регистрация и вход

Регистрация: имя (1–80 символов после обрезки пробелов), пароль (8–128 символов), повтор пароля. Email и телефон не нужны. Пробелы в пароле не удалять. Имя не является уникальным логином: профиль один, на экране входа достаточно пароля и отображения имени.

Пароль не хранить открытым текстом. Решение для версии 1: Web Crypto, PBKDF2-HMAC-SHA-256, случайная соль 16 байт, 600 000 итераций, результат 32 байта; соль и проверочное значение хранятся в Base64 вместе с параметрами. При недоступном API показать объяснение и не заменять его слабым самодельным хешированием. Проверить доступность в обоих целевых браузерах при запуске через file://.

После регистрации пользователь входит автоматически. Сессия существует только в оперативной памяти: перезагрузка и закрытие страницы требуют повторного ввода пароля. «Выйти» очищает состояние сессии и скрывает календарь, но сохраняет финансовые данные. В профиле можно менять имя, часовой пояс и пароль; изменение пароля требует текущего пароля и повторения нового.

Это локальная блокировка интерфейса, а не защита от человека с доступом к файлам браузера или инструментам разработчика. Финансовые данные в localStorage и JSON не шифруются. Кратко объяснить это при регистрации. Восстановления по почте и секретного обходного пароля нет. В случае утраты пароля данные из ранее сделанной JSON-копии можно загрузить в новый локальный профиль в другом браузере; импорт до входа в существующий профиль запрещён.

Исключение для восстановления доступа: на экране входа доступно «Заменить профиль из резервной копии». Это не вход в старый профиль и не раскрытие его данных. Сначала выбрать JSON и пройти всю проверку раздела 14, затем задать новое имя и пароль. До финального подтверждения ничего не записывать. Показать явное предупреждение, что старый профиль и данные, отсутствующие в копии, будут потеряны, и запросить ввод слова «ЗАМЕНИТЬ». Только затем одной записью заменить корень хранилища новым профилем и проверенными данными, закрыть старые сессии через revision и войти в новый профиль. Новая revision равна предыдущей плюс один. При отмене, неверном файле или ошибке записи старый профиль остаётся целиком. Это единственный сценарий импорта без входа; он не сбрасывает пароль с сохранением текущих скрытых данных.

При внешнем изменении auth в другом окне закрыть сессию и потребовать новый вход; revision без проверки auth сама по себе не считается выходом. Сравнение выполнять при storage event и возвращении фокуса.

## 4. Экраны и внешний вид

### 4.1. Основной экран

Верхняя область содержит заголовок «Платёжный календарь на [месяц] [год]», переходы на предыдущий/следующий месяц, выбор месяца и года, «Сегодня», «Добавить операцию», управление строками/группами, экспорт/импорт и профиль. Не выводить карточки общей выручки, прибыли или другие дополнительные показатели.

Отдельное поле «Остаток на начало месяца» сопровождается подписью источника: «Введено вручную» либо «Прогноз из предыдущего месяца». Есть действие возврата к автоматическому остатку, кроме первого месяца учёта.

Основная область — единая горизонтальная таблица:

1. Закреплённый слева столбец названий.
2. Столбцы всех дней месяца с числом и сокращённым днём недели.
3. Верхний блок «Доходы» с дневными суммами и строками клиентов.
4. Нижний блок «Мои расходы» с дневными суммами, необязательными группами и строками расходов.
5. Нижняя строка «Прогнозный остаток» на каждый день.
6. Правый столбец «Итого» для строк и блоков. Для остатка это значение последнего дня, а не сумма остатков.

Заголовки дней закреплены при вертикальной прокрутке, столбец названий — при горизонтальной. Строка прогнозного остатка закреплена у нижней границы области таблицы. Горизонтальный бегунок доступен внизу этой области даже при большом числе строк. Закреплённые части не перекрывают ячейки и друг друга. Правый столбец итогов прокручивается вместе с днями.

У всех закреплённых ячеек непрозрачный фон. Слои: обычные ячейки z-index: 0, закреплённый столбец 10, верхняя и нижняя закреплённые строки 20, их пересечения с левым столбцом 30. Окна и подсказки располагаются выше таблицы. Проверить углы при одновременной вертикальной и горизонтальной прокрутке.

Рекомендуемые размеры: столбец названий 240 px, день не уже 110 px, основная область занимает доступную высоту окна. Целевой минимум окна — 1280×720; при меньшей ширине допустима прокрутка, но элементы управления не должны перекрывать друг друга.

### 4.2. Оформление и состояния

Светлый фон, читаемый системный шрифт, тонкие границы таблицы, спокойные фисташковые акценты кнопок и разделителей. Зелёный статус исполнения должен отличаться от фоновых декоративных акцентов.

| Состояние | Отображение |
| --- | --- |
| Плановый доход/расход | Нейтральная ячейка операции |
| Полученная часть дохода | Зелёная, текст «Получено», установленный флажок |
| Оплаченная часть расхода | Оранжевая, текст «Оплачено», установленный флажок |
| Неоплаченный остаток с датой раньше сегодняшней | Красная, текст «Просрочено» |
| Отрицательный дневной остаток | Светло-красный фон и видимый знак минус |
| Сегодня | Контур/маркер в заголовке дня, не перекрашивающий операции |

Цвет назначается конкретной операции/части, а не всей ячейке дня с несколькими платежами. Исполненные части не становятся красными из-за прошедшей даты. Сегодняшний неоплаченный платёж ещё не просрочен.

Деньги отображать с разделением тысяч, символом ₽ и двумя десятичными знаками. Полное длинное название доступно при наведении и в редакторе. Кнопки с иконками имеют подписи/подсказки и доступные имена. Все формы работают с клавиатуры; Esc закрывает окно без применения, Enter отправляет форму вне многострочного комментария. При закрытии редактора несохранённые изменения отбрасываются, данные календаря до «Сохранить» не меняются.

Уточнение компактного вида: только внутри карточек операций можно скрывать дробную часть ,00; ненулевые копейки всегда показывать полностью. В итогах, остатках и редакторе сохранять два знака. Карточка содержит флажок, сумму и короткую текстовую метку статуса отдельной строкой; назначение — в подсказке при наведении/фокусе и в редакторе. Текст статуса не убирать полностью ради цвета. Несколько карточек располагаются вертикально; первые три видны, остальные раскрываются кнопкой «Ещё N» в этой ячейке. При раскрытии строка увеличивается, все карточки остаются доступны для перетаскивания; есть «Свернуть». Полный расчёт всегда включает и скрытые карточки. Если сумма не помещается в минимальную ширину, расширить столбец до необходимой ширины; не обрезать цифры, не уменьшать шрифт до нечитаемого и не округлять сумму.

## 5. Даты, открытие и навигация

Часовой пояс профиля по умолчанию Asia/Yekaterinburg; его можно изменить на валидный IANA timezone. «Сегодня» вычисляется через Intl.DateTimeFormat в часовом поясе профиля, независимо от системного пояса Windows. Настройка влияет на текущую дату, просрочку и дату по умолчанию при оплате.

Даты операций — календарные строки YYYY-MM-DD, месяцы — YYYY-MM, без времени и UTC-конвертации. При смене часового пояса уже назначенные даты не меняются. Обновлять сегодняшнюю дату при возвращении фокуса страницы и раз в минуту, не перемещая принудительно пользователя по таблице.

Проверку также выполнять при visibilitychange в видимое состояние и перед командами изменения данных. Минутный таймер только сравнивает дату, а не перерисовывает таблицу каждый раз; в скрытой вкладке приостановить его. Если дата не изменилась, DOM не менять. При смене суток обновить только маркер дня, статусы просрочки и подписи, сохранив прокрутку, фокус и введённые поля; завершение активного перетаскивания не прерывать. Это сохраняет обновление просрочки у пользователя, который просто смотрит на открытую страницу в полночь.

После входа открывать текущий месяц и прокручивать таблицу так, чтобы текущий день был виден. Кнопка «Сегодня» повторяет это действие. При переходе в другой месяц показывать начало месяца; при возвращении в текущий — текущую дату. Год выбирается непосредственно, не только многократными нажатиями стрелок. Рабочий диапазон дат версии 1 — 1900–2100 включительно.

## 6. Строки, группы и сортировка

Строка дохода представляет клиента, строка расхода — статью. Пользователь добавляет и переименовывает их. Тип существующей строки не меняется; ошибочную операцию можно перевести в другую строку через редактор, пока в ней нет исполненных частей.

Названия строк и групп: 1–120 символов после trim. Для сравнения дубликатов применять Unicode NFC, trim и приведение к нижнему регистру по русской локали. Не разрешать одинаковые названия строк одного типа (в том числе в разных группах и архиве) и одинаковые названия групп. Доход и расход могут называться одинаково. При совпадении с архивной строкой предложить восстановить её; молча не объединять записи. Эти правила применяются также при переименовании и импорте.

У расходов доступны необязательные именованные группы, например «Кредиты», «Дом», «Работа». Одна строка входит максимум в одну группу, вложенных групп нет. Доходы не группируются. Строки без группы идут отдельной областью «Без группы». Группа — организационный заголовок, не дополнительная денежная операция; двойной учёт групповых сумм исключён.

В настройках строк доступны добавление, переименование, назначение группы, архивирование/восстановление, изменение порядка стрелками или перетаскиванием за отдельный маркер. Удалять можно только строки без каких-либо ссылок из операций и серий. Иначе предлагать архивирование. Удаление группы не удаляет строки: они переходят в «Без группы».

Архивная строка не предлагается для новых операций, но отображается в месяце, если в нём есть её активные или исполненные суммы. Существующие платежи остаются редактируемыми. Архивирование не останавливает повторения автоматически: рядом явно сообщить, что серию нужно остановить отдельно. Отменённые операции доступны в истории строки, в том числе архивной.

По умолчанию каждый блок сортируется по сумме учитываемых операций за выбранный месяц, по убыванию. У доходов сравниваются доходные суммы, у расходов — положительные величины расходов. Сравнивать исполненные части плюс неоплаченные остатки, исключая отменённые суммы. При равенстве — имя по русской локали, затем ID для устойчивости.

При группах расходов сортировать группы по их сумме и строки внутри каждой группы по их сумме; «Без группы» участвует в той же сортировке. Ручное изменение порядка переключает соответствующий блок в «Свой порядок». Ручной порядок общий для всех месяцев. Доступно возвращение к «По сумме ↓». Пересортировку выполнять после сохранения операции, но не во время её перетаскивания. Полностью пустые активные строки остаются видны с нулевыми итогами.

order — положительное целое число в своей области: все доходные строки, строки каждой расходной группы (включая «Без группы») и заголовки групп расходов. Новому элементу присвоить max(order) + 1 в его области, пустой области — 1; учитывать архивные строки. Положение системной области «Без группы» хранить отдельно в settings.ungroupedExpenseOrder. При успешном ручном перемещении из режима автосортировки сначала зафиксировать текущий видимый порядок соответствующего блока в order = 1…N (для расходов отдельно группы и строки внутри них); невидимые архивные строки добавить в конец своей области в прежнем порядке. Затем применить перемещение и перенумеровать затронутые области. Всё сохранить одной командой. Отменённое перетаскивание порядок и режим не меняет. Возврат к автосортировке не стирает сохранённые order; перенос статьи между группами добавляет её в конец целевой области и уплотняет порядок исходной.

## 7. Создание и редактирование операций

Два равноправных способа: кнопка «Добавить операцию» и двойной щелчок по свободной области ячейки строки/дня. Во втором случае подставить строку, тип и дату. В ячейке с операциями предусмотреть небольшую кнопку «+», чтобы можно было добавить ещё одну.

Поля: тип, строка клиента/статьи, общая сумма, плановая дата, необязательное назначение до 200 символов, комментарий до 2000 символов, настройка повторения для новой операции. Из формы можно создать новую строку. По умолчанию дата — сегодня в текущем месяце или первое число просматриваемого месяца.

Все суммы операций положительны и заданы с точностью до копейки. Разрешить ввод запятой или точки и пробелов-разделителей; неоднозначные форматы и больше двух знаков после разделителя отклонять, а не молча округлять. Сумму разбирать из строки в целые копейки. Введённое значение и все результаты должны оставаться безопасными целыми числами JS; переполнение запрещает сохранение с пояснением.

Несколько операций в одной строке/дне показываются отдельными карточками, каждая со своей суммой, статусом и действиями. Внутри ячейки порядок стабильный: по времени создания части, затем ID. Нажатие на карточку открывает редактор. Нажатие на флажок или начало перетаскивания не открывает редактор одновременно.

Редактор показывает общую сумму, исполненные части, неоплаченный остаток и отменённую сумму. Это сведения конкретной операции, не отдельная аналитика. Изменение общей суммы ниже уже исполненной плюс отменённой суммы запрещено: сначала необходимо исправить соответствующие части.

## 8. Исполнение, частичные оплаты и снятие флажка

У обязательства одна общая сумма и не более одного неоплаченного остатка с одной плановой датой. Разбиение ещё не оплаченного остатка на несколько будущих дат не реализуется.

Флажок на плановой карточке открывает компактное окно подтверждения исполнения: сумма по умолчанию равна остатку, дата — сегодня. Пользователь может изменить оба значения. Сохранение создаёт исполненную часть; отмена окна не меняет флажок и данные. Это необходимо, чтобы поддержать частичную оплату и фактическую дату.

При сумме меньше остатка отображаются исполненная часть на фактическую дату и остаток на прежнюю плановую дату. При равной сумме остаток исчезает. Допускаются несколько последовательных частичных оплат.

Если новая оплата превышает остаток, в окне явно показать, что общая сумма увеличится до суммы всех исполнений плюс отменённая часть. После сохранения увеличить исходную сумму обязательства; отдельного дохода не создавать. Например, ожидаемые 30 000 ₽ при получении 35 000 ₽ становятся обязательством на 35 000 ₽ с полным исполнением. Будущие повторения это не изменяет.

Снятие флажка с конкретной исполненной части немедленно отменяет только эту часть, без дополнительного подтверждения. Её сумма возвращается в общий неоплаченный остаток на сохранённую плановую дату обязательства. Если остаток уже был перенесён, возвращённая сумма объединяется с ним на новой дате. Остальные оплаты остаются исполненными. Если остатка не было, он появляется на последней сохранённой плановой дате. Дата снятой фактической оплаты не заменяет плановую дату.

Сумму и дату исполненной части можно исправить в редакторе; пересчитать остаток. Если после увеличения исполнения превышена общая сумма, применить описанное правило увеличения общей суммы с явным показом нового значения. Нельзя назначить фактическую оплату позже сегодняшнего дня: для будущего использовать плановую операцию. Изменение типа/строки при наличии исполненных частей запрещено; исправлять через отмену исполнений и редактирование.

## 9. Переносы, просрочка и отмена действий

Перетаскивать можно только плановую карточку/остаток, удерживая левую кнопку мыши. Допустимы любые дни видимого месяца, не только соседние. Меняется только плановая дата; строка, тип и исполненные части не меняются. Другая строка или область вне дней — недопустимая цель, отпускание там не меняет данные. Для точного переноса доступен редактор даты, в том числе на другой месяц.

При приближении к краю прокручиваемой области выполнять горизонтальную автопрокрутку. Подсвечивать допустимую дату назначения. Esc отменяет незавершённый перенос. Перенос на тот же день — отсутствие изменения. Подтверждение переноса не спрашивать.

Просрочен остаток больше нуля с плановой датой строго раньше сегодняшней. Он остаётся на своей дате, окрашивается красным и учитывается в прогнозе на этой дате до ручного переноса. Автоматического переноса просрочки нет. Перетаскивание просрочки работает как обычного остатка; цвет после переноса определяется новой датой.

После переноса и снятия флажка показывать сообщение с «Отменить» на 10 секунд. Отмена восстанавливает финансовое состояние до последнего такого действия. Следующая команда изменения data или auth, выход или перезагрузка отменяет доступность этой команды; просмотр месяца и запись служебной отметки экспорта в текущем окне её не отменяют.

Уточнение хранения Undo: снимок до действия и срок команды существуют исключительно в оперативной памяти. В localStorage записывается результат нажатия «Отменить», то есть восстановленные финансовые данные, а не снимок или стек Undo. Команда проходит обычную проверку revision и запись; при конфликте или ошибке записи не применять восстановление только в памяти. revision при Undo увеличивается, а не откатывается к значению снимка. Служебные метаданные экспорта и настройки профиля не восстанавливаются из финансового снимка.

## 10. Отмена обязательств и удаление

«Отменить остаток» переносит всю оставшуюся сумму в отменённую часть, исключая её из календарных расчётов; исполненные части сохраняются. Потребовать подтверждение. Общая сумма обязательства не меняется. Отмена всей ещё не оплаченной операции — тот же механизм.

Отменённые части доступны через «История отмен» в управлении строками: строка, назначение, текущая отменённая сумма и «Плановая дата операции» (актуальная plannedDate). Это список действующих отменённых остатков, а не журнал всех прошлых отмен; исторические даты и события отмен отдельно не хранятся. Восстановление возвращает всю cancelledMinor в неоплаченный остаток и обнуляет cancelledMinor. Выбранная дата становится единой plannedDate всего остатка, включая ранее существовавший R. Например, 5 000 ₽ на 10-е плюс восстановленные 3 000 ₽ с датой 15-е дают единые 8 000 ₽ на 15-е. Перед сохранением явно показать итоговую сумму и дату. В основной таблице отдельные отменённые суммы не показывать.

«Удалить операцию» предназначено для ошибочных записей: подтверждение указывает сумму и наличие фактических оплат; после согласия удаляются всё обязательство и его исполнения. Для экземпляра серии сохраняется отметка подавления, чтобы он не появился вновь. Удалённое не показывается в истории отмен; восстановление возможно из резервной копии. Не реализовывать массовое удаление всех данных отдельной кнопкой.

## 11. Ежемесячные повторения

Параметры серии: строка, сумма, назначение, комментарий, первый месяц, число 1–31, необязательный последний месяц включительно, флажок «Переносить выходные на ближайший следующий рабочий день». Интервал только один месяц.

Для каждого исходного месяца сначала взять указанное число, ограничив его последним числом месяца. Затем, если включён флажок, сдвинуть субботу на понедельник и воскресенье на понедельник. Рабочие дни здесь — только понедельник–пятница; государственные праздники и рабочие субботы не учитываются. Сдвиг может перейти в следующий месяц или год. Идентичность экземпляра при этом определяется исходным месяцем серии, а отображение — фактической плановой датой. Последний месяц ограничивает исходные месяцы, а не итоговую дату после переноса выходного.

Повторения по умолчанию плановые. Не переносить исполненный статус, частичные оплаты и изменённую общую сумму одного экземпляра на следующий.

Изменение отдельной операции имеет варианты «Только этот платёж» и «Этот и будущие». Перетаскивание всегда относится только к текущему экземпляру. Редактирование серии применяется от исходного месяца выбранного экземпляра включительно. Все экземпляры с исполнениями сохраняются целиком; индивидуально изменённые, отменённые и удалённые экземпляры также сохраняют свои исключения. В окне изменения серии прямо указать, что ранее изменённые вручную платежи сохранятся. Остальные плановые экземпляры получают новые параметры.

Исключение из сохранения ручных правок — сам выбранный экземпляр: если у него нет исполнений, cancelledMinor = 0 и он не удалён, «Этот и будущие» заменяет его целиком новыми параметрами серии, удаляя прежнее исключение. Новая дата рассчитывается по выбранному числу и правилу выходных, прежний ручной перенос сбрасывается. Предварительно показать старую/новую дату и сумму. Исходный месяц этого экземпляра обязан входить в диапазон новой версии. Если у выбранного экземпляра есть исполнения или отменённая часть, он сохраняется целиком; окно явно сообщает, что изменится правило серии, но этот платёж останется прежним. Для него доступно отдельное редактирование «Только этот платёж». Остальные ручные исключения, включая удаления, не сбрасываются. Нельзя автоматически удалять исключение только по условию отсутствия исполнений: оно может содержать отменённые деньги.

Остановка серии задаёт последний исходный месяц. Уже исполненные экземпляры и ручные исключения за этой границей не удаляются; пользователь может отменить их отдельно. Показать это перед сохранением. Саму серию с историей не удалять физически.

Технически использовать виртуальную генерацию экземпляров из правил и сохранённые исключения. Уникальный ключ экземпляра: seriesId + ':' + sourceMonth. Повторное открытие месяца не создаёт новых копий. Все операции над экземпляром сохраняют его полное исключение; удаление — tombstone. Для расчёта месяца учитывать также сдвинутые экземпляры предыдущего исходного месяца и любые ручные исключения, перенесённые из других месяцев. При генерации исходный виртуальный экземпляр всегда заменяется исключением по ключу, а не добавляется к нему.

## 12. Остатки, итоги и переходы между месяцами

Обозначения для обязательства: A — общая сумма, P — сумма действующих исполнений, C — отменённая сумма, R = A − P − C. Все величины неотрицательные целые копейки, R не может быть отрицательным.

Для каждого дня d:

- Доходы I(d) = фактические доходные части с датой d + доходные остатки R с плановой датой d.
- Расходы E(d) = фактические расходные части с датой d + расходные остатки R с плановой датой d.
- B(d) = B(d−1) + I(d) − E(d); для первого дня B(d−1) — начальный остаток месяца.

Общая сумма A сама по себе в календарь не добавляется. Отменённые части не входят в I и E. Это исключает двойной учёт. Смена статуса без смены даты и суммы не меняет прогноз. При фактической дате, отличной от плановой, денежный поток переносится на фактическую дату в размере исполнения.

Месячные суммы строки/блока — сумма дневных потоков выбранного месяца. Они включают только части и остатки, датированные этим месяцем; общая сумма обязательства, разбросанного по месяцам, не показывается полностью в каждом из них. Прогнозный остаток может быть отрицательным и не блокирует операции.

Первый месяц учёта задаётся при первом входе вместе с ручным начальным остатком (по умолчанию текущий месяц и 0 ₽). До него просмотр разрешён, но добавление операций и серий запрещено. Чтобы начать раньше, в настройках можно сдвинуть первый месяц назад и ввести его начальный остаток; прежние ручные месячные значения сохранить. Перенос первого месяца вперёд не поддерживается.

Первый месяц всегда имеет ручной остаток. Для последующих автоматический начальный остаток равен прогнозу конца предыдущего месяца, включая промежуточные месяцы, которые пользователь ещё не открывал, и их повторения. Ручное значение является самостоятельной точкой отсчёта и имеет приоритет; ноль — полноценное ручное значение. Изменения предшествующих месяцев не перезаписывают его. Расчёт выбранного месяца можно начинать с ближайшего предшествующего ручного остатка.

Возврат «Использовать прогноз предыдущего месяца» удаляет ручное переопределение и немедленно пересчитывает текущий и зависящие месяцы. Автоматический перенос не создаёт доход. Начальные остатки могут быть отрицательными.

Конечные остатки месяцев кэшировать в оперативной памяти в Map по YYYY-MM; кэш не сохранять в JSON. Для изменения обычного платежа определить все затронутые месяцы по его потокам до и после изменения (включая старую и новую даты переноса). Для каждого такого месяца инвалидировать его и зависимые последующие до следующего ручного начального остатка, не затрагивая сам следующий ручной месяц, если в нём не менялись потоки. Если изменение затрагивает несколько участков, обработать каждый: перенос через ручную точку отсчёта нельзя ограничить одним первым участком. При изменении серии, первого месяца, импортировании или восстановлении профиля разрешён полный сброс кэша. Изменение только ручного остатка инвалидирует цепочку от его месяца. Кэш дневных потоков, если используется, инвалидируется отдельно по изменившимся потокам. Для промежуточных месяцев без отображения рассчитывать месячные суммы без построения DOM и всех дневных ячеек. Повторная отрисовка без изменений использует кэш, но его отсутствие не должно менять результат.

Если работа начинается в середине месяца, введённая сумма всё равно считается остатком на первое число. Пустые ранние дни показывают её без изменений. Отдельного фактического баланса «на сегодня» и восстановления пропущенных движений нет.

## 13. Модель данных

Основной ключ localStorage: paymentCalendar.v1. Хранить один JSON-документ, а не разрозненные несогласованные ключи. Схема:

| Объект | Поля |
| --- | --- |
| Корень | schemaVersion: 1, revision: целое, updatedAt: ISO timestamp, auth, data, localMeta |
| localMeta | lastExportRequestedAt: ISO timestamp/null, changesSinceExport: неотрицательное целое; по умолчанию null и 0; отсутствующие поля при чтении старого документа получают эти значения |
| auth | displayName, passwordAlgorithm: PBKDF2-SHA-256, iterations, saltBase64, verifierBase64 |
| data.settings | timeZone, currency: RUB, firstMonth, incomeSortMode, expenseSortMode, ungroupedExpenseOrder: положительное целое |
| data.openingBalances | словарь YYYY-MM → целые копейки; только ручные значения |
| data.groups[] | id, name, order |
| data.rows[] | id, type: income/expense, name, groupId/null, order, archived: boolean |
| data.operations[] | самостоятельные обязательства с полями ниже |
| data.series[] | id, versions[]; версия: effectiveFrom, firstMonth, lastMonth/null, rowId, amountMinor, dayOfMonth, shiftWeekend, title, comment |
| data.exceptions[] | occurrenceKey, seriesId, sourceMonth, deleted: boolean, operation/null |
| Обязательство | id, rowId, amountMinor, plannedDate, title, comment, cancelledMinor, settlements[], createdAt, updatedAt |
| Исполненная часть | id, amountMinor, actualDate, createdAt |

Тип обязательства определяется строкой; не хранить второй изменяемый тип, способный разойтись с ней. Для серии выбирать последнюю версию с effectiveFrom не позже исходного месяца, затем проверять границы firstMonth/lastMonth. Версии имеют уникальные effectiveFrom и хранятся по возрастанию. При изменении «этот и будущие» заменить версии начиная с выбранного исходного месяца одной новой версией; более ранние версии сохранить.

ID создаются через crypto.randomUUID либо UUID из crypto.getRandomValues; не использовать только timestamp. Производные остатки, дневные суммы, просрочка и цвет не являются источником истины и вычисляются заново. Сессия и команда Undo не экспортируются и не сохраняются.

Вне временной метки обновления календарные даты не интерпретировать как UTC. Все изменения состояния проходят через единую валидацию и сохранение. Сначала подготовить и проверить новую копию состояния, затем успешно записать JSON, после этого заменить состояние в памяти и перерисовать интерфейс. При ошибке записи прежние данные остаются действующими, сообщение об успешном сохранении не показывается.

## 14. Резервное копирование и импорт

«Скачать JSON» выгружает весь финансовый набор data, schemaVersion, exportedAt и имя профиля для справки. Имя файла: payment-calendar-YYYY-MM-DD-HHmm.json по часовому поясу профиля. Пароль, соль, проверочное значение и сессия в экспорт не входят. Экспорт содержит все месяцы, архивные строки, отмены, правила и исключения серий, ручные остатки.

Рядом с кнопкой компактно показывать «Экспорт: ещё не выполнялся» либо дату/число дней с последнего запуска экспорта. Подсвечивать кнопку фисташковым акцентом, если экспорта не было, прошло не менее 7 календарных дней в часовом поясе профиля либо выполнено не менее 20 сохраняемых изменений data после экспорта. Это служебная подсказка, не финансовая аналитика и не всплывающее уведомление. Успешная команда изменения data (включая Undo и импорт) увеличивает changesSinceExport на 1; просмотр, таймер, генерация виртуальных экземпляров, вход и смена пароля не увеличивают его. При обычном импорте дату предыдущего экспорта сохранять: импорт не означает новую копию текущего состояния.

После формирования файла и запуска браузерного скачивания установить localMeta.lastExportRequestedAt и обнулить счётчик. Не утверждать, что файл действительно сохранён: веб-страница не подтверждает завершение скачивания. Подсказка: «Последний запуск экспорта; проверьте файл в загрузках». localMeta не экспортируется, а в новом/восстановленном профиле начинается с null и 0. Изменение localMeta увеличивает revision как любая запись, но не считается изменением data и не сбрасывает Undo в текущем окне. Если запись метаданных не удалась, скачивание не считать ошибочным; сообщить отдельно, что отметку экспорта сохранить не удалось.

«Загрузить JSON» доступно после входа; отдельное восстановление нового профиля с экрана входа описано в разделе 3.1 и использует тот же валидатор. Ограничение размера — 10 MiB. До изменения данных проверить синтаксис, schemaVersion, обязательные типы полей, валидность дат, безопасные целые суммы, UUID/ключи, уникальность ID, названий и порядок элементов по разделу 6, ссылки, границы серий, часовой пояс, инвариант A ≥ P + C, наличие ручного остатка первого месяца. Неизвестную версию отклонять. Не применять неподдерживаемые поля как код или разметку; конструировать разрешённую схему явно.

Затем показать сводку количества строк, операций и серий и предупреждение о полной замене финансовых данных. Действия: «Скачать текущую копию», «Заменить данные», «Отмена». Импорт не объединяет записи. Имя, пароль и текущая авторизация локального профиля сохраняются; настройки календаря, включая часовой пояс, заменяются данными файла. После успешного импорта открыть текущий месяц и показать результат.

При любой ошибке проверки, отмене или ошибке записи исходные данные остаются неизменными. Резервная копия пригодна для восстановления в новом профиле другого браузера без знания старого пароля.

## 15. Ошибки, устойчивость и ограничения среды

- При недоступном localStorage на запуске показать блокирующее пояснение: сохранение недоступно; не изображать рабочий календарь с сохранёнными изменениями.
- При повреждённом сохранённом JSON не создавать пустой профиль поверх него. Предложить скачать исходную строку для восстановления; дальнейший сброс только как отдельная явно подтверждённая процедура восстановления, не автоматическое действие.
- При исчерпании квоты оставить прежнее состояние, предложить скачать резервную копию. Не удалять историю автоматически.
- file://-хранилище зависит от браузера и расположения файла. Не обещать доступность данных после перемещения папки, между Chrome и Яндексом или в приватном режиме. Краткая справка рекомендует экспорт перед переносом.
- Не утверждать, что очистка обычного HTTP-кэша обязательно удаляет localStorage или что данные file:// удаляются «в первую очередь»: это не требование и не гарантированное поведение браузера. Поведение localStorage для file:// не стандартизовано; отдельно предупредить об удалении данных при очистке хранилища браузера и проверить фактическое сохранение в целевых браузерах.
- Защита от двух окон: хранить revision, проверять её перед записью. При внешнем изменении через storage event либо несовпадении revision остановить сохранение и предложить перечитать данные. ТЗ не обещает полноценные транзакции между вкладками; параллельное редактирование двумя окнами не поддерживается.
- Пользовательские названия и импортированный текст выводить через textContent/безопасные DOM-операции, не вставлять через innerHTML. Никаких eval и выполнения содержимого JSON.
- Поля показывают ошибки рядом с местом ввода, введённые значения при ошибке сохраняются в форме. Не показывать технический stack trace пользователю.
- При ошибке расчёта/переполнении не выводить NaN или ложные нули; отклонить вызвавшее изменение и показать причину.

## 17. Проверяемые критерии приёмки

### 17.1. Числовые проверки

1. Начальный остаток 10 000 ₽; доход 30 000 ₽ на 5-е и расход 12 000 ₽ на 6-е: дни 1–4 = 10 000 ₽, день 5 = 40 000 ₽, день 6 и последующие без операций = 28 000 ₽.
2. В этом примере получение 20 000 ₽ на 5-е и перенос остатка 10 000 ₽ на 8-е даёт: день 5 = 30 000 ₽, день 6 = 18 000 ₽, день 8 = 28 000 ₽. Доход за месяц остаётся 30 000 ₽.
3. Перенос оставшихся 10 000 ₽ в следующий месяц уменьшает доход первого месяца на 10 000 ₽ и добавляет его во втором; факт 20 000 ₽ остаётся на 5-м.
4. Снятие флажка с 20 000 ₽ при остатке 10 000 ₽ на 8-е даёт единый плановый остаток 30 000 ₽ на 8-е; факт на 5-е исчезает.
5. Получение 35 000 ₽ по исходному плану 30 000 ₽ увеличивает A до 35 000 ₽, P до 35 000 ₽, R до нуля; нет второй операции на 5 000 ₽.
6. Начальный остаток 1 000 ₽ и расход 1 500 ₽ дают −500 ₽ и светло-красную ячейку, без блокировки.
7. Конец месяца 28 000 ₽ автоматически задаёт начало следующего 28 000 ₽. После ручного изменения на 25 000 ₽ изменение предыдущего месяца не меняет 25 000 ₽. Возврат в автоматический режим использует актуальный прогноз.
8. Ручной нулевой остаток не заменяется автоматическим ненулевым.
9. При A = 30 000 ₽, P = 20 000 ₽ отмена остатка даёт C = 10 000 ₽, R = 0; в потоке остаются только 20 000 ₽. Восстановление возвращает 10 000 ₽ на выбранную дату.

### 17.2. Даты и повторения

10. Серия на 31-е: февраль 2027 → 28 февраля, февраль 2028 → 29 февраля при выключенном переносе выходных.
11. Серия на 31 января 2026 с переносом выходных отображается 2 февраля 2026, но сохраняет sourceMonth = 2026-01. Повторное открытие января и февраля не создаёт дублей.
12. Одиночный перенос экземпляра не изменяет последующие месяцы. Удалённый экземпляр не появляется после перезагрузки или изменения серии.
13. Прямой переход через несколько месяцев учитывает все промежуточные повторения при расчёте остатка.
14. В часовом поясе профиля вчерашний остаток красный, сегодняшний нейтральный. Смена даты при открытой вкладке обновляет просрочку без ручной перезагрузки.
15. Переход из декабря в январь, високосный февраль и возврат кнопкой «Сегодня» работают корректно.

### 17.3. Пользовательские действия и сохранность

16. Оба способа добавления работают, в одной ячейке доступны несколько независимых карточек.
17. Перетаскивание не открывает редактор, не меняет строку и не требует подтверждения; недопустимая цель и Esc оставляют данные прежними.
18. Исполненные части не перетаскиваются, но редактируются через форму. Снятие одного флажка не отменяет остальные части.
19. Новые данные сохраняются после перезагрузки и повторного входа. Пароль открытым текстом отсутствует в localStorage и экспортном файле.
20. После регистрации финансовый интерфейс недоступен через обычные элементы интерфейса без входа. Неверный пароль не открывает календарь; выход и перезагрузка закрывают сессию.
21. Экспорт → импорт в чистый профиль воспроизводит расчёты, серии, исключения, группы, архивы и ручные остатки. Пароль нового профиля остаётся действующим.
22. Повреждённый JSON, неизвестная версия, неверные ссылки, повторные ID и неверные суммы не меняют текущие данные.
23. Ошибка localStorage не сопровождается ложным «Сохранено». Внешняя новая revision не перезаписывается без перечитывания.
24. Закреплённые дни, названия и прогноз остаются видимыми при прокрутке; горизонтальная полоса доступна; длинные тексты и несколько карточек не перекрываются.
25. Начальное открытие фокусирует текущую дату; календарь работает без сетевых запросов, без ошибок консоли в обычных сценариях.

### 17.4. Проверки уточнений после ревью

26. Undo восстанавливает финансовые данные и сохраняет результат с новой revision; перезагрузка не возвращает команду Undo, в JSON нет снимка. Метаданные экспорта не откатываются.
27. Создание строк в автосортировке и переход к ручному порядку не перемешивают остальные строки; отмена переноса не меняет order. Архивные строки и «Без группы» сохраняют определённый порядок.
28. Восстановление 3 000 ₽ при существующем остатке 5 000 ₽ переносит все 8 000 ₽ на выбранную дату. В истории показана текущая плановая дата, а не выдуманная историческая.
29. «Этот и будущие» на ранее перенесённом плановом экземпляре обновляет выбранный экземпляр и серию; исключения других месяцев сохраняются. Исполненный или отменённый выбранный экземпляр остаётся прежним с явным объяснением в форме.
30. Кэшированные результаты равны расчёту с нуля после переноса через ручной месячный остаток, изменения серии и Undo. Повторная отрисовка не пересчитывает всю цепочку.
31. При четырёх карточках доступны три и «Ещё 1»; после раскрытия четвёртая перетаскивается. Ненулевые копейки и длинные суммы видны полностью. Углы закреплённых областей не просвечивают при диагональной прокрутке.
32. Названия «Дом» и « дом » в одной области не создают дубликаты; финансовый импорт с такими дубликатами отклоняется без изменения данных.
33. На видимой странице минутная проверка без смены дня не перерисовывает DOM. Смена суток сохраняет открытый редактор, введённые поля и прокрутку.
34. Неверный JSON, отмена или ошибка записи при восстановлении с экрана входа сохраняют старый профиль. Успех требует нового пароля и явного подтверждения замены, не раскрывает старые данные.
35. После 20 изменений либо 7 дней кнопка экспорта получает акцент; запуск экспорта сбрасывает счётчик и показывает именно дату запуска, не неподтверждённое успешное сохранение файла.

## 18. Организация реализации и проверки

Внутри app.js логически отделить хранение/валидацию, локальный вход, календарные даты, генерацию повторений, расчёт потоков, команды изменения состояния и отрисовку. Чистые расчётные функции не должны читать DOM. Все денежные изменения идут через единый слой команд, а не прямое изменение значений в ячейках.

Для перетаскивания выбрать Pointer Events: pointerdown/move/up с pointer capture. Порог начала — 5 CSS px от точки нажатия; до порога действие считается кликом. Не начинать перенос с флажка или кнопки. pointercancel, потеря захвата и Esc отменяют перенос и автопрокрутку; после завершённого переноса подавить следующий связанный click. Автопрокрутка через requestAnimationFrame: зона 32 px от края, скорость плавно увеличивается к краю, максимум 600 px/с с учётом времени кадра. Захват указателя не использовать для определения ячейки назначения: вычислять её по координатам и видимым границам, учитывая закреплённый столбец. Призрак перетаскивания не перехватывает события. Выбор API не заменяет проверку в обоих браузерах и не является гарантией отсутствия ошибок.

Для автоматических тестов экспортировать чистые функции через условный CommonJS-блок `if (typeof module !== 'undefined' && module.exports) { module.exports = { /* чистые функции */ }; }`. Инициализацию интерфейса вызывать только при наличии window/document; обращения к DOM, localStorage и запуск таймеров не должны выполняться на верхнем уровне при загрузке файла в Node. Node применяется только разработчиком для тестов, не требуется пользователю и не меняет поставку из трёх файлов. Разделить app.js на явно обозначенные секции/замыкания и тестировать публичные функции расчёта, не копируя их реализацию в тесты.

Проверить числовые и календарные правила автоматическими тестами чистых функций; тестовые материалы не включать в три поставляемых файла. Вручную пройти основные сценарии в Chrome и Яндекс Браузере именно при file://, включая регистрацию, сохранение после повторного запуска, drag-and-drop и JSON. Проверять на копиях данных, не изменять исходный Excel. Если какой-либо целевой браузер недоступен для проверки, явно указать это в отчёте, не заявлять о пройденном тесте.

Финальная поставка реализации: три работающих файла и краткое описание запуска, выполненных проверок и известных ограничений. Не загружать демонстрационные финансовые операции автоматически; первый календарь пустой, кроме выбранного начального остатка.

## 19. Будущий серверный этап — вне реализации версии 1

Планируются полноценная регистрация, серверная авторизация, работа при закрытой странице и обе интеграции: Telegram и Google Календарь. Время напоминаний задаётся в настройках профиля с учётом выбранного часового пояса. Желаемый формат Telegram — одно короткое сообщение со списком неоплаченных расходов на завтра; полученные доходы и исполненные расходы туда не включаются. Конкретное представление событий Google Календаря и согласование их с ежедневным сообщением проектируются на серверном этапе.

Переносы, частичные оплаты и отмены должны обновлять будущие напоминания без дубликатов. Для этого сохраняются устойчивые ID операций и частей. Первая версия не содержит секретов API, фиктивной отправки и элементов настройки времени уведомлений, которые ещё не работают. Мобильный интерфейс и синхронизация также требуют отдельного этапа и дополнения ТЗ.

## 20. Решения по внешнему ревью

| Замечание | Решение и причина |
| --- | --- |
| Неоднозначное хранение Undo | Принято: снимок только в RAM, восстановленные данные записываются обычной командой |
| Порядок новых строк и переход от автосортировки | Принято: определены области order, присвоение и фиксация видимого порядка |
| Склейка восстановленной и плановой суммы | Принято: одна общая сумма остатка и одна выбранная дата |
| Несуществующая история прежних дат отмены | Принято упрощение: показывать актуальную плановую дату, не обещать журнал событий |
| Индикатор резервной копии | Принято с уточнением: отмечать запуск экспорта, не гарантировать сохранение скачанного файла; метаданные локальные |
| Редактирование выбранного исключения серии | Принято с защитой отменённых сумм и исполнений; сброс только чисто планового выбранного исключения |
| Кэширование месячных расчётов | Принято с обработкой обеих сторон переноса и нескольких ручных точек отсчёта |
| Переполнение ячеек | Принято частично: компактная сумма, раскрытие карточек, но текст статуса остаётся доступным без наведения |
| Дубликаты названий | Принято: единая проверка при создании, переименовании и импорте |
| Удаление локального пароля | Отклонено: пароль согласован пользователем; принято поэтапное восстановление из копии в новый профиль |
| Удаление минутной проверки даты | Отклонено: просрочка должна обновляться и без действий; вместо этого запрещена лишняя перерисовка и остановлен таймер скрытой вкладки |
| Разделение версии серии на независимые серии | Отклонено: без дополнительного переноса/подавления исключений новая серия может восстановить удалённые или продублировать изменённые экземпляры. Сохранены стабильные ключи и версии |
| Несколько JS-файлов | Отклонено: три файла — явное требование; приняты логическое разделение app.js и независимость расчётного ядра |
| Автокоррекция суммы | Частично уже предусмотрено: точка/запятая и пробелы допустимы. Буквы и неоднозначные разделители не исправлять молча, деньги не округлять автоматически |
| Слои закреплённых областей | Принято: задан порядок наложения и проверка углов |
| Pointer Events | Принято как выбор реализации, без обещания автоматической безошибочности |
| Экспорт чистых функций для тестов | Принято вместе с изоляцией браузерной инициализации, иначе один module.exports не решает проблему |

Технические справочные основания: [MDN: localStorage и ограничения file://](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage), [MDN: Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events), [Node.js: CommonJS и module.exports](https://nodejs.org/api/modules.html). Утверждение ревью о первоочередном удалении localStorage при очистке кэша не принято как установленный факт.
